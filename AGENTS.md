# Основная информация
- Проект называется MeetSpace
- Для Backend используй ASP.NET Core, EF Core (Npgsql), Postgres, AWSSDK.S3, MiniO, JWT Bearer, Bcrypt, AutoMapper, Swagger, xUnit
- Для Frontend используй TS, React, webpack, babel, eslint, stylelint, prettier, библиотеку компонентов Mantine, Phosphor Icons, classnames, Redux, React Router, dotenv-webpack, Jest

## Правила написани кода
- Для бкенда применяются следующие правила:
    - Для бэкенда используй clean architecture, разделяя всё на слои: 
        - Api - слой связанный с web, в котором описываются, эндпоинты, контроллеры, политики, например CORS, DTO и др связанное с web
        - Domain - слой, в котором описаны основные сущности, использующиеся в приложении
        - DataAccess - слой связанный с БД, в котором прописаны операции с БД (добавление, удаление, изменение записей и тд), также инициализация соединения с БД тоже проходит здесь и др операции, которые связаны с БД
        - Application - слой в котором, описана бизнес логика без опоры на сторонние библиотеки и тд. Здесь описываются стандартные сервисы, абстракции и тд
        - Infrastructure - здесь находятся реализации сервисов, которые взаимодействуют с внешними сервисами, т.е. здесь могут быть реализации, которые вызывают сторонние API, другие хранилища, например, S3 и др
    - Используй DI
    - Старайся придерживатся принципа Single Responsobility
    - А также помни, что модули должны зависеть от абстракций
    - Следи за тем, чтобы не допускалась ошибка n+1 запроса

- Для фронтенда применяются следующие правила:
    - Все взаимодействия fetch операции с api должны проходить в папке src/services/
    - нельзя использовать `!important` в стилях
    - никаких z-index: 100 или 1000, ставь нормальные значения, например 1 или 2 и тд.
    - используемые цвета, должны быть использованы из переменных, т.е. нельзя `#ffffff`, но можно keyword `white`, переменные `var(--white-color)`, `var(--mantine-white)` и тд
    - если всё таки нужен какой-то точный цвет, например,  #ff5005, то кастомные переменные должны быть в main.css
    - не надо вписывать в зависимости useEffect и других хуков то, что не надо: надо записывать туда лишь те объекты, изменения которых должны заново запустить логику хука
    - не надо вписывать в зависимости useEffect и других хуков то, что не будет меняться, например, какие-нибудь labels, которые не меняются на протяжении всего пользования приложением
    - DTO должны быть в отдельных файлах
    - предки должны позиционировать компоненты, а не сами компоненты, т.е. если у нас есть страница, а на ней есть кнопка, мы должны `margin` у этой кнопке задавать на странице, а не в самой кнопке
    - Не используй inline стили с ключевым словом `style`, используй либо встроенные свойства для стилей в библиотеку компонентов, например, как `size`, либо создавай одноимённый `.css` файл и прописывай стили там. Старайся писать как можно меньше мусорных стилей, которые ничего не делают. Стили в `.css` пиши, применяя BEM-методологию
