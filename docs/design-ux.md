# MeetSpace — UX-документ: страницы и пользовательские взаимодействия

> Тикет: UX-001 «Описание страниц и пользовательских взаимодействий».
> Источники: `AGENTS.md`, `goal.md`, тикет UX-001.
> Результат тикета: этот файл (`docs/design-ux.md`).
> Объём документа: только описание UX. Без кода, макетов, прототипов и технической архитектуры.

---

## 1. Введение

Документ детализирует перечень страниц из `goal.md`: состав блоков, действия пользователя, реакцию системы, переходы, поля форм и правила валидации, а также сквозные сценарии. Документ не противоречит `goal.md` и расширяет его только в части UX-деталей.

### 1.1. Что входит в задачу

- Описание всех страниц из `goal.md`.
- Переходы между страницами.
- Поля форм и правила валидации (включая бизнес-правила бронирования).
- Сквозные сценарии, затрагивающие несколько страниц.
- Отдельный раздел «Различия по ролям» (Пользователь / Менеджер).
- Единая цветовая палитра и адаптивные правила (десктоп / планшет / мобайл).

### 1.2. Что НЕ входит (границы задачи)

- Код, макеты, прототип, техническая архитектура.
- Глубокий разбор empty/loading/error-состояний: описывается основной happy path; реакция системы на ошибку указывается кратко там, где это часть действия.
- Отдельный раздел по доступности (a11y) и детальные карты редиректов/хлебных крошек.

## 2. Общие принципы и конвенции

### 2.1. Роли

- **Пользователь (User)** — управляет только своими бронированиями.
- **Менеджер (Manager)** — дополнительно редактирует и удаляет любые бронирования, а также загружает фото комнат.

Подробная матрица прав — раздел 6.

### 2.2. Карта страниц

Публичная зона (без авторизации):
- Вход
- Регистрация

Авторизованная зона (app-shell):
- Главная
- Комнаты
- Календарь
- Мои бронирования
- Настройки
- Профиль

### 2.3. App-shell и навигация

Оболочка приложения единая для всех авторизованных страниц.

**Верхняя панель (TopBar)** — общая для всех размеров:
- Логотип MeetSpace (слева) → кликабелен, ведёт на «Главную».
- Основная навигация: **Главная**, **Комнаты**, **Календарь**, **Мои бронирования**.
- Быстрое действие: кнопка «+ Бронь» (открывает «Главную» с фокусом на поиске слота).
- Меню пользователя (аватар): **Профиль**, **Настройки**, **Выйти**.
- Переключатель темы (светлая/тёмная) — вынесен в TopBar и дублируется в «Настройках».

**Раскладка по устройствам:**
- **Десктоп (≥ 1200):** боковая панель (Sidebar) слева с иконками + подписями, сворачиваемая; основная навигация дублируется в Sidebar. TopBar тонкий, содержит логотип, поиск-кнопку, меню пользователя, тему.
- **Планшет (768–1199):** навигация — TopBar с кнопкой-гамбургером, открывающей Drawer со списком пунктов; либо компактный TabBar сверху. Карточки сетки 2 колонки.
- **Мобайл (< 768):** навигация — нижний TabBar (Главная, Комнаты, Календарь, Мои); TopBar только с аватаром и темой. Сетки 1 колонка. Модальные окна — на весь экран.

### 2.4. Цветовая палитра

Принципы (из `AGENTS.md`): цвета берутся из переменных, без литералов вроде `#ffffff`; точные значения выносятся в `main.css` как кастомные переменные. Ниже — семантические токены, которые определяются в `main.css` и ссылаются на палитру Mantine.

**Акцент и смысловые цвета:**
- `--accent` — синий (основной акцент): первичные действия, активный пункт навигации, ссылки, фокус-кольцо, **свои бронирования**.
- `--booking-others` — оранжевый: **чужие бронирования** в календаре/планировщике.
- `--success` — зелёный: подтверждение, успешное бронирование/сохранение.
- `--danger` — красный: удаление, отмена, ошибки валидации.
- `--warning` — янтарный: конфликт времени, предупреждения (например, пересечение слотов при выборе).

**Поверхности и текст (светлая тема):**
- `--bg` — `var(--mantine-color-gray-0)` (фон приложения)
- `--surface` — `var(--mantine-white)` (карточки, модальные)
- `--surface-2` — `var(--mantine-color-gray-1)` (вложенные блоки, шапки таблиц)
- `--text` — `var(--mantine-color-gray-9)`
- `--text-muted` — `var(--mantine-color-gray-6)` (подписи, метаданные)
- `--border` — `var(--mantine-color-gray-3)`

**Тёмная тема (`[data-mantine-color-scheme="dark"]`):**
- `--accent` → `var(--mantine-color-blue-5)`
- `--booking-others` → `var(--mantine-color-orange-5)`
- `--bg` → `var(--mantine-color-dark-8)`
- `--surface` → `var(--mantine-color-dark-7)`
- `--surface-2` → `var(--mantine-color-dark-6)`
- `--text` → `var(--mantine-color-gray-2)`
- `--text-muted` → `var(--mantine-color-gray-5)`
- `--border` → `var(--mantine-color-dark-4)`

**Соответствие правилам фронтенда:** все цвета используются только через переменные (`var(--accent)` и т. п.); в `main.css` задаются кастомные переменные, ссылающиеся на токены Mantine. Литеральных hex-значений в компонентах нет.

### 2.5. Иконки

Библиотека **Phosphor Icons**. Семантика:
- Главная — `House`, Комнаты — `MapPin`/`Conference`, Календарь — `Calendar`, Мои бронирования — `CalendarCheck`, Настройки — `Gear`, Профиль — `UserCircle`, Выйти — `SignOut`, Бронь — `Plus`, Удалить — `Trash`, Редактировать — `PencilSimple`, Фото — `Camera`/`Image`.

### 2.6. Адаптивные брейкпоинты

| Диапазон | Контрольный размер | Сетка карточек | Навигация |
|---|---|---|---|
| Десктоп | ≥ 1200 | 3 колонки | Sidebar |
| Планшет | 768–1199 | 2 колонки | TopBar + Drawer |
| Мобайл | < 768 | 1 колонка | Нижний TabBar |

### 2.7. Обратная связь (общее)

- Успех — короткий toast (`Notification` Mantine) с цветом `--success` и иконкой `Check`.
- Ошибка действия — toast с цветом `--danger` и иконкой `Warning`.
- Ошибка валидации поля — текст под полем, цвет `--danger`, обводка поля.
- Длительные операции (загрузка списка, брони) — индикатор `Loader` в области действия; кнопки блокируются.

## 3. Страницы

Для каждой страницы: **Назначение · Блоки и элементы · Действия и реакция системы · Переходы · Поля форм и валидация · Адаптив**.

### 3.1. Вход

**Назначение.** Аутентификация существующего пользователя по email и паролю.

**Блоки и элементы**
- Публичная раскладка: по центру карточка, слева/сверху логотип MeetSpace.
- Форма входа:
  - Email (текстовое поле с иконкой `Envelope`).
  - Пароль (поле с переключателем видимости `Eye`/`EyeSlash`).
  - Кнопка «Войти» (primary, `--accent`).
  - Ссылка «Нет аккаунта? Зарегистрироваться».
- Баннер/сообщение об ошибке формы (над кнопкой, появляется при ошибке).

**Действия и реакция системы**
- Отправка формы → валидация полей. При успехе: выдача access+refresh токенов, переход на «Главную» (или на ранее запрошенную страницу, если был редирект на вход). При ошибке учётных данных — общая ошибка «Неверный email или пароль» (без раскрытия, что именно неверно).
- Переключатель видимости пароля — локальное переключение типа поля.
- Ссылка «Зарегистрироваться» → переход на «Регистрацию».

**Переходы**
- → Главная (успешный вход).
- → Регистрация.

**Поля форм и валидация**
- Email — обязателен, формат `email`.
- Пароль — обязателен.

**Адаптив.** Одна колонка, максимальная ширина карточки ~420px, центрирование. На мобайл — карточка во весь экран по ширине, поля растянуты.

---

### 3.2. Регистрация

**Назначение.** Создание новой учётной записи. Новому пользователю назначается роль «Пользователь».

**Блоки и элементы**
- Та же публичная раскладка, что у входа.
- Форма регистрации:
  - Имя.
  - Фамилия.
  - Email.
  - Пароль (с переключателем видимости).
  - Подтверждение пароля.
  - Кнопка «Зарегистрироваться».
  - Ссылка «Уже есть аккаунт? Войти».

**Действия и реакция системы**
- Отправка формы → валидация. При успехе: авто-вход, назначение роли «Пользователь», переход на «Главную». При занятом email — ошибка «Пользователь с таким email уже существует» у поля email. При несовпадении паролей — ошибка у поля подтверждения.

**Переходы**
- → Главная (успех).
- → Вход.

**Поля форм и валидация**
- Имя, Фамилия — обязательны, непустые.
- Email — обязателен, формат `email`, уникален (проверка на сервере).
- Пароль — обязателен, минимум 6 символов.
- Подтверждение пароля — обязательно, должно совпадать с паролем.

**Адаптив.** Аналогично странице входа; поля в одну колонку.

---

### 3.3. Главная

**Назначение.** Центральная страница: поиск и фильтрация комнат, карусель комнат, детальная карточка комнаты с планировщиком слотов и формой бронирования. Это основная точка создания брони.

**Блоки и элементы**
1. **Приветствие/hero** — краткий заголовок и быстрый поиск по названию.
2. **Панель фильтров**:
   - Название комнаты (текст).
   - Дата (date-picker).
   - Время начала / время окончания (time, шаг 15 мин).
   - Вместимость (число или select: 1–2, 3–5, 6–10, 10+).
   - Оборудование — multi-select чипами: Проектор, Доска, Телевизор, ВКС, Wi-Fi, Кондиционер.
   - Этаж (select).
   - Кнопки «Применить» (primary) и «Сбросить» (subtle).
3. **Карусель комнат** — горизонтальная лента карточек: фото, название, этаж, вместимость, краткий список оборудования (иконки), бейдж доступности, кнопка «Подробнее».
4. **Карточка деталей комнаты** (Drawer/Modal):
   - Большое фото (карусель фото при наличии).
   - Название, этаж, вместимость, описание.
   - Полный список оборудования.
   - **Планировщик слотов** на выбранную дату: шкала 09:00–18:00, шаг 15 минут. Занятые слоты подсвечиваются: свои — `--accent` (синий), чужие — `--booking-others` (оранжевый). Свободные интервалы кликабельны.
   - **Форма бронирования**: название, описание, дата, время начала, время окончания, кнопка «Забронировать».
5. Кнопка «Все комнаты» → переход на «Комнаты».

**Действия и реакция системы**
- Применить фильтры → обновление карусели/списка доступных комнат (кнопка блокируется, показывается `Loader`).
- Сбросить → фильтры возвращаются к значениям по умолчанию, список обновляется.
- «Подробнее» → открывается карточка деталей с планировщиком; время в форме предзаполняется из фильтров (если заданы).
- Выбор свободного интервала в планировщике → время начала/окончания автоматически подставляется в форму бронирования.
- «Забронировать» → проверка бизнес-правил. Успех: toast `--success` «Бронирование создано», кнопка в toast «Перейти к моим бронированиям». Конфликт времени: toast `--danger` «Комната занята в этом интервале», подсветка конфликтующего слота в планировщике. Прочие нарушения (вне 09–18, окончание раньше начала, прошлое время) — ошибки у соответствующих полей формы.

**Переходы**
- → Комнаты (кнопка «Все комнаты»).
- → Мои бронирования (из toast после успешной брони, либо прямая ссылка).
- Карточка деталей не уводит со страницы — бронирование происходит на месте.

**Поля форм и валидация (бронирование)**
- Название — обязательно, непустое.
- Описание — необязательно.
- Дата — обязательна.
- Время начала — обязательно.
- Время окончания — обязательно.
- Бизнес-правила (`goal.md`):
  - Интервал в пределах рабочего дня 09:00–18:00.
  - Окончание позже начала.
  - Нельзя бронировать в прошлом.
  - Отсутствие пересечения с другими бронями этой комнаты.
  - Дата/время хранятся без таймзоны.

**Адаптив.**
- Панель фильтров на планшете/мобайле сворачивается в Drawer, открываемый кнопкой «Фильтры».
- Карусель — горизонтальный скролл/свайп; на мобайле карточки по ширине экрана.
- Карточка деталей: на десктопе — Drawer справа, на мобайле — full-screen Modal.
- Планировщик: на мобайле превращается в вертикальный список слотов («09:00–09:15 свободно» и т. д.) с переключателем «Свободные/Все».

### 3.4. Комнаты

**Назначение.** Полный каталог комнат с поиском, деталями и формой бронирования.

**Блоки и элементы**
- **Панель поиска** (упрощённая по сравнению с главной): название, этаж, вместимость, оборудование.
- **Сетка карточек комнат** (3 / 2 / 1 колонки по брейкпоинтам): фото, название, этаж, вместимость, бейджи оборудования, бейдж доступности, кнопки «Подробнее» и «Забронировать».
- **Карточка деталей комнаты** (Drawer/Modal) — идентична карточке на главной (фото, описание, оборудование, планировщик, форма бронирования). Поведение и валидация те же.

**Действия и реакция системы**
- Поиск/фильтрация → обновление сетки.
- «Подробнее» → карточка деталей с планировщиком.
- «Забронировать» → открывает карточку деталей с фокусом на форме бронирования (или сразу на планировщике).
- Бронирование — как на главной (те же реакции и ошибки).

**Переходы**
- Карточка → форма бронирования (без ухода со страницы).
- → Мои бронирования (после успешной брони, через toast).
- → Главная (через логотип/навигацию).

**Поля форм и валидация.** Совпадают с формой бронирования на главной (см. 3.3).

**Адаптив.** Сетка 3→2→1 колонки. Карточка деталей — Drawer (десктоп/планшет) / full-screen Modal (мобайл). Фильтры сворачиваются в Drawer на мобайле.

---

### 3.5. Календарь

**Назначение.** Календарный вид бронирований за диапазон; рабочий день 09:00–18:00, шаг 15 минут; свои и чужие брони подсвечиваются разными цветами.

**Блоки и элементы**
- **Переключатель вида**: «День» / «Месяц».
- **Селектор даты** (для вида «День» — конкретный день; для «Месяц» — месяц с навигацией ←/→).
- **Вид «День»**: вертикальная шкала 09:00–18:00, комнаты как колонки (десктоп) либо одна колонка с блоками (планшет/мобайл). Блоки броней:
  - свои — `--accent` (синий),
  - чужие — `--booking-others` (оранжевый).
  - При наведении — мини-карточка: название, время, комната, автор (для менеджера — всегда; для пользователя — только для чужих брони показывается имя автора, редактирование недоступно).
- **Вид «Месяц»**: сетка дней; в каждой ячейке — мини-индикаторы броней (точки/полоски синего и оранжевого) и счётчик. Клик по дню → переключение в вид «День» этой даты.
- **Кнопка «+ Бронь»** → открывает выбор комнаты/слота (форма бронирования).
- Действия на блоке своей брони: «Редактировать», «Удалить».
- Действия на блоке чужой брони: для пользователя — только просмотр; для менеджера — «Редактировать», «Удалить».

**Действия и реакция системы**
- Переключение вида → смена представления того же диапазона.
- Смена даты/месяца → загрузка броней диапазона (индикатор `Loader` в области сетки).
- Клик по своей брони → меню действий; «Редактировать» открывает форму (предзаполненную), «Удалить» → подтверждение → удаление.
- Клик по чужой брони → мини-карточка с деталями; для менеджера дополнительно доступны «Редактировать»/«Удалить».
- «+ Бронь» → выбор комнаты и свободного слота (в модальном планировщике) → форма бронирования с предзаполненными временем/комнатой. Валидация и реакции — как на главной.
- Успешное создание/редактирование/удаление → toast `--success` и обновление сетки без перезагрузки страницы.

**Переходы**
- → форма бронирования (модальная, не уводит со страницы).
- → Мои бронирования (ссылка из toast/меню).
- → Главная (быстрое бронирование через навигацию).

**Поля форм и валидация.** Создание/редактирование — как на главной (3.3). При редактировании текущая бронь исключается из проверки пересечений (`goal.md`).

**Адаптив.**
- Вид «День»: на десктопе — колонки-комнаты; на планшете — одна колонка с блоками по шкале; на мобайле — вертикальный список броней дня («09:30–10:30 · Переговорная А · своя»).
- Вид «Месяц»: ячейки упрощаются до индикаторов + счётчика; на мобайле — компактная сетка с тапом по дню.

---

### 3.6. Мои бронирования

**Назначение.** Список бронирований текущего пользователя; создание, редактирование, удаление.

**Блоки и элементы**
- **Фильтры/вкладки**: «Предстоящие / Прошедшие / Все».
- **Поиск** по названию брони.
- **Дополнительный фильтр**: по комнате, по диапазону дат.
- **Список карточек брони**: название, описание, комната (с мини-фото), дата, время начала–окончания, статус (предстоящая/прошедшая), кнопки «Изменить» и «Отменить».
- **Форма редактирования** (Modal): поля как при создании.
- **Модальное подтверждение удаления**.
- Кнопка «+ Бронь» → переход на «Главную» для выбора комнаты/слота.

**Действия и реакция системы**
- «Изменить» → форма редактирования (предзаполнена). Сохранение → валидация → успех: toast `--success`, карточка обновляется. Конфликт времени → ошибка у поля времени / toast `--danger`.
- «Отменить» → модальное подтверждение «Удалить бронирование?» → подтверждение → удаление → toast `--success`, карточка исчезает из списка (или переходит в «Прошедшие» в зависимости от логики; здесь — удаляется).
- «+ Бронь» → переход на «Главную».
- Переключение вкладок/фильтров → фильтрация списка.

**Переходы**
- → Главная (через «+ Бронь»).
- Редактирование происходит в Modal без ухода со страницы.
- После удаления остаёмся на странице.

**Поля форм и валидация (редактирование)**
- Те же поля, что при создании: название, описание, дата, время начала, время окончания, комната.
- Бизнес-правила те же; при проверке пересечений текущая бронь исключается.

**Адаптив.** Список — одна колонка на всех размерах (карточки во всю ширину). Кнопки «Изменить»/«Отменить» на мобайле — иконки-кнопки в строке карточки; форма редактирования — full-screen Modal.

---

### 3.7. Настройки

**Назначение.** Переключение темы оформления (светлая/тёмная).

**Блоки и элементы**
- Раздел «Оформление»: переключатель «Тёмная тема» (Mantine `Switch`).
- Информационный блок: язык интерфейса — «Русский» (фиксированный, недоступен для изменения — отображается как заблокированное поле, чтобы пользователь понимал, что других языков нет).

**Действия и реакция системы**
- Переключение темы → немедленное применение темы ко всему приложению; выбор сохраняется (профиль/локально). Тема применяется глобально, в том числе к цветам броней (синий/оранжевый корректируются по тёмной палитре).
- Изменение языка недоступно — элемент не интерактивен.

**Переходы.** Страница не требует переходов; взаимодействует со всеми страницами через глобальную тему.

**Адаптив.** Простая раскладка в одну колонку, без изменений по брейкпоинтам.

---

### 3.8. Профиль

**Назначение.** Редактирование имени, фамилии, email, фото профиля; выход из аккаунта.

**Блоки и элементы**
- Аватар (крупно) с кнопкой «Заменить фото» (иконка `Camera`); превью нового фото перед сохранением.
- Форма: Имя, Фамилия, Email, кнопка «Сохранить».
- Блок безопасности/аккаунта: кнопка «Выйти из аккаунта» (subtle/danger).

**Действия и реакция системы**
- «Заменить фото» → выбор файла → загрузка во временное превью → при «Сохранить» файл отправляется в хранилище; аватар обновляется в шапке и в меню пользователя. Ошибка загрузки → toast `--danger`.
- «Сохранить» → валидация; успех → toast `--success`, изменения применяются в шапке (имя/аватар). Занятый email → ошибка у поля.
- «Выйти» → очистка токенов → переход на «Вход».

**Переходы**
- → Вход (после выхода).
- После сохранения остаёмся на странице.

**Поля форм и валидация**
- Имя, Фамилия — обязательны, непустые.
- Email — обязателен, формат `email`, уникален (при изменении — проверка на сервере).

**Адаптив.** Простая центрированная колонка (~560px), аватар и форма в столбик; на мобайле — на всю ширину.

## 5. Сквозные сценарии

Сценарии согласованы с описаниями страниц выше.

### Сценарий A. Регистрация → первая бронь
1. **Регистрация**: пользователь заполняет форму → успех, авто-вход → переход на **Главную**.
2. **Главная**: применяет фильтры (дата, оборудование) → выбирает комнату в карусели → «Подробнее».
3. В карточке деталей выбирает свободный слот в планировщике → заполняет название → «Забронировать».
4. Toast `--success` → тап «Перейти к моим бронированиям» → **Мои бронирования** → новая бронь в списке «Предстоящие».

### Сценарий B. Поиск → бронирование → изменение
1. **Главная** или **Комнаты**: фильтрация → выбор комнаты → слот → «Забронировать» (успех).
2. **Мои бронирования** → карточка брони → «Изменить» → смена времени в Modal → «Сохранить».
3. Валидация (с исключением текущей брони из проверки пересечений) → успех → карточка обновляется.

### Сценарий C. Поиск → бронирование → отмена
1. Создание брони (как в B).
2. **Мои бронирования** → «Отменить» → подтверждение → удаление → toast `--success`.

### Сценарий D. Календарь → создание брони → проверка
1. **Календарь**, вид «День» → выбор даты.
2. «+ Бронь» → выбор комнаты и свободного слота → форма → «Забронировать».
3. Новый блок брони появляется в сетке (синий, «своя»).
4. Переход в **Мои бронирования** подтверждает наличие брони.

### Сценарий E. Смена темы
1. **Настройки** (или переключатель в TopBar) → включение «Тёмной темы».
2. Тема применяется глобально; в **Календаре** цвета броней переходят на тёмные варианты синего/оранжевого.
3. Выбор сохраняется и применяется при следующем входе.

### Сценарий F. Менеджер: правка чужой брони из Календаря
1. **Календарь**, вид «День» → блок оранжевой (чужой) брони → меню.
2. Менеджер выбирает «Редактировать» → форма (предзаполнена) → меняет время → «Сохранить».
3. Успех → блок обновляется (остаётся оранжевым — чужая бронь).

### Сценарий G. Менеджер: загрузка фото комнаты
1. **Комнаты** (или **Главная**) → карточка деталей комнаты.
2. Зона «Фото комнаты» → «Загрузить фото» → выбор файла → превью → «Сохранить».
3. Новое фото появляется в галерее комнаты (доступно всем пользователям).
